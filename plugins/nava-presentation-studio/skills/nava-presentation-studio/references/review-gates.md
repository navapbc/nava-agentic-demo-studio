# Review gates

Use two distinct review passes for substantial decks. The author may perform both, but each pass must adopt the reviewer role and record concrete defects before repairing them. Use an independent agent only when delegation is available and authorized.

## Evidence reviewer

Review the slide plan before visual authoring.

- Reconstruct the chronology. A later experiment must not appear to precede the capability that enabled it.
- Attribute enabling work before its downstream result. Translate technical work into the capability it created without erasing the people who built it.
- For every number, verify source, owner or attribution, date, task boundary, unit, denominator, model or architecture when material, and caveat.
- Reject false waterfalls. Session cost, per-application cost, small fixture cost, subscription usage, and marginal API cost are different measures unless proven otherwise.
- Prefer paired case studies over a dramatic composite when only some stages are like-for-like.
- Make intermediate enabling work visible when it explains the result: instrumentation, evaluation, data plumbing, architecture, or safety boundaries.
- Remove claims whose evidence is only a remembered label, ambiguous chart, or unverified transcription.

The pass is complete when every quantitative slide can answer: “Compared with what, doing the same task, under which conditions?”

## Visual reviewer

Review the rendered deck, not only the source.

- Inspect every slide at presentation size and at thumbnail size.
- A contact sheet verifies pacing, not spacing. Record each slide's full-size review as pass or a concrete defect; do not declare the deck clean from thumbnails alone.
- Inspect wrapped title baselines against the main content, not just object bounds. Check labels, captions, chart strokes, and timeline paths for collisions. Recheck these relationships after copy edits or moving a compound visual.
- Flag cramped title/body relationships, inconsistent section gaps, accidental alignment, undersized screenshots, unreadable footnotes, and text that was shrunk instead of edited.
- Flag any unassigned blank region larger than roughly one quarter of the canvas. Keep it only when it creates deliberate contrast or pacing.
- Flag empty bullets, orphan icons, placeholder labels, clipped objects, distorted images, and partial diagrams.
- Confirm the dominant idea is visually dominant and the supporting explanation is nearby but clearly secondary.
- Confirm product evidence is large enough to read. If the interface is the point, give it at least half the slide or a full-slide treatment.
- Check the sequence for three or more repeated compositions and for a missing visual climax.
- Compare the delivered deck with the usable archetypes in its template or reference deck. Flag a deck that technically matches the brand but uses only a narrow, repetitive subset without a narrative reason.
- Flag three consecutive text-first slides with the same background, title position, and density unless they form an intentional series.
- Confirm that color fields, photography, screenshots, charts, quotes, diagrams, and large-statement treatments are used only where their evidence or narrative role warrants them—but are not omitted simply because a generic text layout is easier.
- Confirm the reveal or ending insight is visibly distinct in the contact sheet.

After repairs, render the changed slides again. A source file that looks tidy in code is not evidence that the presentation is ready.
